按你的设计文档出稿，屏与文档里的九个前端页面模块一一对应，并标出 V1 与 V1.5 的边界。核心闭环是绑定伴侣、加入共同挑战、每日打卡、累计进度与成就，所以首页的主角是挑战进度和今天有没有打卡，不是纪念日。视觉沿用你选的克制中性底 + 单一强调色。

设计基底

强调色只出现在三个地方：主操作按钮、进度已完成的部分、当前选中项。其余交给中性色和留白。刻意避开粉红＋爱心的品类默认，用胭脂红做唯一情绪色。

V1 核心闭环对应 auth / couple / challenge / checkin

按文档的闭环顺序排。绑定是第一个流失点，所以邀请页只做一件事；打卡是留存的全部，所以首页必须一眼看出今天打没打。

V1.5 扩展对应 moment / anniversary / achievement / dashboard

这四块都建立在已经有打卡数据之上，所以放在核心闭环之后。时光记录按文档只有文本、心情和可见性——没有图片位，界面就不留图片位。

今日打卡卡片的四个状态首页同一个位置

这个位置每天被看一次，是全产品最重要的一块面积。强调色只跟着「现在该做的那一件事」走：没绑定时是绑定，今天没打卡时是打卡，挑战结束后是开下一个。已完成态一律不上色——强调色一旦出现在已完成态，用户就学不会「有颜色＝该做事」。

落地约束来自文档的非目标与业务规则

这一节是给实现看的。文档里写明不做的东西，界面上必须提前把位置让出来，否则会做出一堆等接口的空壳。

V1 不做的功能怎么影响界面

没有推送和短信

提醒只能靠首页那块强调底和日历缺口

没有图片和文件存储

记录只有文本；徽章用字符和 CSS，不引图

没有第三方登录

注册页不留微信位

没有实时聊天

互动落在打卡备注和时光记录上

没有商城和支付

积分只做成绩，别放「我的积分」入口

积分这条要特别小心：叫积分，用户就会去找兑换的地方。第一版它只是进度的另一种说法，所以只在挑战进度和成就里出现，不给它独立页面。

「催 TA 打卡」同理。没有推送就做不到，如果要保留这个动作，它只能是对方下次打开时看到的一条标记，文案不能写成已发送提醒。

前端不自己算业务规则

能不能打卡、连续多少天、多少积分、进度百分比，全部取服务端返回的字段，本地只做展示。三个具体后果：

今天的日期边界以服务端为准

跨零点本地算会两边不一致

唯一约束命中不是报错

直接刷新成已完成态，并写出提交人

并发提交要有专门文案

不能落到「网络错误」

双方同时点提交是这个产品最常见的竞态：文档用唯一约束和条件更新兜住了数据，但界面上失败的那一方看到的不该是失败——他看到的应该是「林刚刚打了今天的卡」。
