# 第 14 章 测试、调试与工程质量

## 本章目标

- 区分 Mapper、Service、Controller 和端到端测试。
- 掌握基本测试场景、MockMvc 和 SQL 验证思路。
- 学会通过首个有效异常、Caused by 和调用栈定位问题。

> 本章是独立学习章节。建议先阅读本章，再完成文末练习，并回到项目中寻找对应代码。

### 14.1 测试分层

| 测试对象 | 关注点 |
|---|---|
| Mapper | SQL、参数绑定、结果映射 |
| Service | 业务规则、异常、事务边界 |
| Controller / MockMvc | 路由、参数、状态码、JSON |
| 端到端流程 | 多个接口和数据库状态是否连贯 |

### 14.2 JUnit 5 基础

先认识这些概念：

- `@Test`：标记测试方法；
- 断言：验证结果是否符合预期；
- 测试前置和清理：准备数据、恢复状态；
- 测试隔离：一个测试不应该依赖另一个测试留下的数据。

当前阶段先为本周修改的类和接口编写定向测试，不运行无关检查。

### 14.3 必须覆盖的错误场景

- 参数校验失败；
- 用户、情侣关系或挑战不存在；
- 邮箱重复；
- 未登录；
- 无权限；
- 事务回滚；
- 乐观锁冲突；
- SQL 结果映射错误。

### 14.4 Debug 流程

```text
确认错误现象
    ↓
查看完整日志
    ↓
找到第一个有效异常
    ↓
优先阅读 Caused by
    ↓
根据调用栈定位文件和方法
    ↓
判断是路由、参数、Bean、SQL、数据库还是业务问题
    ↓
只修改最接近根因的位置
    ↓
用同一个场景重新验证
```

### 14.5 常见错误定位

| 现象 | 优先检查 |
|---|---|
| 启动时找不到 Bean | 注解、包扫描、构造方法依赖 |
| 接口 404 | 类级路径、方法级路径、HTTP 方法 |
| 请求体为空 | JSON 字段名、DTO、`@RequestBody` |
| 校验不生效 | `@Valid`、`@Validated`、校验依赖 |
| Mapper 找不到 SQL | namespace、id、XML 路径 |
| SQL 参数为空 | 参数名、`@Param`、对象属性名 |
| 查询字段为空 | 列名、属性名、驼峰映射、resultMap |
| 修改影响行数为 0 | WHERE 条件、版本号、记录是否存在 |
| 重复数据 | Service 查重、唯一约束、并发场景 |
