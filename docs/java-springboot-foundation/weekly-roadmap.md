# 每周学习路线

## 产品设计入口

完整的前后端模块设计见：[产品设计：我们的冒险](../couple-challenge-design.md)。

当前执行原则：

```text
先完成后端核心闭环
    ↓
用接口工具和定向测试验证
    ↓
后端结业
    ↓
再创建 frontend/ 开始前端
```

## 基础补课阶段：进入第 1 周前

### 阅读章节

- 第 1 章：变量、类型、对象；
- 第 2 章：方法，重点阅读；
- 第 3 章：类、接口、泛型；
- 第 4 章：集合和常用方法；
- 第 5 章：异常和注解；
- 第 6 章：Maven 和项目结构。

### 练习目标

1. 能读懂 `User` 类的字段、构造方法和 Getter / Setter；
2. 能解释 `UserService` 的参数、返回值和调用链；
3. 能区分请求 DTO、数据库 Entity 和响应 VO；
4. 能说出 `List<User>` 中泛型的作用；
5. 能解释业务异常如何转换为 HTTP 响应；
6. 能根据产品设计文档画出用户、情侣、挑战和打卡的关系。

### 基础验收

请用自己的话回答：

```text
一个 Java 方法由哪些部分组成？
UserService 为什么需要 UserMapper？
一个对象从哪里创建？
为什么 Controller 不直接调用 Mapper？
为什么后端接口不能只相信前端提交的用户 id？
```

## 第 1 周：用户数据库 CRUD

对应详细计划：[第 1 周：用户数据库 CRUD](../weekly/week-01-database-crud.md)

### 需要阅读

- 第 1、2、6 章：类型、方法和项目结构；
- 第 9 章：HTTP 方法和参数绑定；
- 第 11 章：SQL 基础；
- 第 12 章：Mapper 和 XML；
- 第 13 章：CRUD 和分页。

### 本周目标

把用户模块的新增、详情、分页、修改和删除全部接入 MySQL，打通：

```text
HTTP → Controller → Service → Mapper → XML SQL → MySQL → JSON
```

### 本周要理解

- 主键、自增和唯一约束；
- Mapper 接口和 XML 的匹配；
- `#{}` 参数绑定；
- Entity 和数据库行的映射；
- `LIMIT`、`OFFSET` 和 `COUNT(*)`。

## 后端完成后：前端阶段

前端不提前进入以上八周任务。后端验收通过后，再开始：

1. 创建 `frontend/` 工程；
2. 完成认证、路由守卫和请求层；
3. 接入情侣绑定和挑战页面；
4. 接入打卡、时光记录和纪念日页面；
5. 最后做成就、移动端和体验优化。

每次新增前端页面前，先确认对应后端 API 已通过接口验证，并且 DTO/VO 契约已经稳定。

## 后续进阶：Redis

Redis 不纳入当前八周后端主线，等后端核心闭环完成、通过验收，并完成前端第一轮联调后再开始。

建议先围绕现有用户模块练习：

1. 为用户详情查询增加缓存；
2. 理解缓存命中、缓存未命中和 TTL；
3. 用户修改、删除后删除对应缓存；
4. 再扩展到邮箱查询缓存、访问次数统计和登录会话；
5. 最后学习缓存一致性、限流和分布式锁。

第一阶段重点是理解 Redis 与 MySQL 的协作关系，不为了使用 Redis 而提前改变当前项目的数据库设计。
