# 第 7 周：部署与项目收尾

> 建议投入：16–20 小时  
> 对应总计划：[PLAN.md](../../PLAN.md)

## 当前目标

把开发机上可运行的项目整理为别人能够启动和验证的交付物：配置可区分环境，秘密信息从环境变量传入，应用与 MySQL 可由 Docker Compose 启动，并具备健康检查、文档和完整业务流程记录。

## 本周完成标准

- [ ] 开发、测试、生产配置职责清晰。
- [ ] 数据库密码与 JWT 密钥通过环境变量传入。
- [ ] 仓库不包含真实密码、Token 或密钥。
- [ ] 应用镜像可在 Apple Silicon 环境构建和运行。
- [ ] Docker Compose 能同时启动应用和 MySQL。
- [ ] 应用等待数据库可用，并有明确的健康状态。
- [ ] 从注册到完成任务的完整业务流程走通。
- [ ] README 包含前置条件、启动方式、验证方式和常见问题。
- [ ] 新开发者只按 README 即可从空环境启动项目。

## 需要创建或调整的内容

- 不同环境的 Spring 配置文件。
- 环境变量示例文件，只放变量名和示例占位值。
- 应用镜像构建文件。
- Docker Compose 配置。
- 健康检查与必要的运行日志配置。
- README、接口说明和数据库关系图。
- 一份端到端请求集合或可复现的 curl 流程。

## 每日安排

### 周一：配置与秘密信息盘点（2–3 小时）

1. 列出当前配置中的数据库地址、账号、密码、JWT 密钥和日志设置。
2. 区分所有环境共享的配置与环境特有配置。
3. 设计开发、测试、生产配置覆盖关系。
4. 将敏感值改由环境变量提供。
5. 搜索仓库，确认没有真实密码、Token 和密钥残留。

当天产出：配置变量清单和环境说明。

### 周二：应用镜像（3 小时）

1. 明确构建阶段和运行阶段分别需要什么。
2. 选择兼容 Java 21 与 Apple Silicon 的基础镜像。
3. 构建应用产物，再构建应用镜像。
4. 单独运行应用容器，观察启动日志和端口。
5. 检查镜像中不包含开发环境秘密信息。

检查题：为什么应用镜像不应该把数据库密码写死在构建文件里？

### 周三：Docker Compose 联动 MySQL（3 小时）

1. 定义应用、MySQL 两个服务和数据库数据卷。
2. 应用通过服务名连接 MySQL，而不是容器内的 `localhost`。
3. 设置所需环境变量和端口映射。
4. 从空数据卷启动，确认迁移自动创建表。
5. 重启服务，确认数据库数据仍然存在。

### 周四：健康检查与日志（3 小时）

1. 提供能表示应用存活和就绪的健康检查。
2. 为 MySQL 配置健康状态，避免只依赖容器启动顺序。
3. 观察数据库未就绪时应用的行为并记录。
4. 日志至少能够看到时间、级别、请求或异常上下文。
5. 确保日志不输出密码、JWT 或完整认证头。

### 周五：文档与关系图（3 小时）

1. README 说明项目目标、技术栈、前置条件和启动命令。
2. 记录环境变量及其用途，但不写真实值。
3. 绘制 users、projects、project_members、tasks 的关系图。
4. 整理核心接口、认证方式和常见状态码。
5. 增加常见启动失败的排查入口。

### 周六：完整业务流程验收（4–5 小时）

从空数据库按顺序执行：

1. 注册负责人 A 和成员 B。
2. A 登录并获取 Token。
3. A 创建项目。
4. A 将 B 添加为成员。
5. B 登录并查看项目。
6. B 创建一条指派给自己的任务。
7. B 修改任务并推进状态直到完成。
8. A 查询任务列表并组合筛选。

保存每一步请求、状态码、关键响应和数据库检查，形成可重复演示脚本或请求集合。

### 周日：陌生环境演练与收尾（2–3 小时）

1. 模拟新开发者，只阅读 README 从空环境启动。
2. 检查是否存在依赖个人目录、IDE 配置或手工数据库操作的隐藏步骤。
3. 按本周交付清单逐项核验。
4. 冻结任务评论模块的实现思路：最终验收前只确认需求，不预先查看或生成答案。
5. 整理最终验收所需的三天时间块。

## 交付验收清单

| 检查项 | 验收方式 |
|---|---|
| 空环境启动 | 按 README 一条流程启动应用与 MySQL |
| 表结构 | 数据库迁移自动执行 |
| 数据持久化 | 重启容器后数据仍存在 |
| 健康状态 | 应用与数据库状态可查看 |
| 秘密信息 | 仓库搜索不到真实密码和密钥 |
| 完整业务流 | 注册至任务完成全程成功 |
| 错误定位 | README 提供日志和常见问题入口 |

## 学习重点

- 配置文件描述结构，环境变量提供环境特有或敏感值。
- 容器内 `localhost` 指向容器自身，服务间通过网络名称访问。
- 启动顺序不代表服务已经可用，健康检查表达真实就绪状态。
- 数据卷与容器生命周期不同，容器重建不应自动丢失数据库数据。
- 可交付项目不仅要“我能运行”，还要让其他人能够复现。

## 周末复盘问题

1. 构建时配置与运行时配置有什么区别？
2. 为什么不能把数据库密码提交到 Git，即使仓库当前是私有的？
3. 应用容器为什么不能使用 `localhost` 连接另一个 MySQL 容器？
4. 容器已启动与应用已就绪有什么区别？
5. 从空环境启动失败时，应按什么顺序检查容器、网络、配置、迁移和应用日志？
