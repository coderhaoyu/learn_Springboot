# 第 3 周：认证与安全

> 建议投入：17–20 小时
> 对应总计划：[PLAN.md](../../PLAN.md)

## 当前目标

实现注册、登录和当前用户接口，理解带 Token 的请求如何在到达业务 Controller 之前建立当前用户身份。

本周只解决“你是谁”，暂时不实现情侣关系和挑战权限。

## 本周完成标准

- [ ] 注册只保存 BCrypt 密码摘要；
- [ ] 登录成功后签发带过期时间的 JWT；
- [ ] `GET /api/users/me` 返回当前用户 VO；
- [ ] 业务接口默认要求登录；
- [ ] 无 Token、错误 Token 和过期 Token 返回 401；
- [ ] 已认证但没有业务权限的请求能够返回 403；
- [ ] 密码、密码摘要和 Token 不出现在响应和日志中。

## 需要创建或调整的职责

- 认证 Controller：注册和登录入口；
- 认证 Service：注册规则、密码比较和 Token 签发；
- 登录和注册 DTO/VO：定义安全边界；
- JWT 工具：生成、解析和验证；
- JWT 过滤器：读取请求头并建立身份；
- Security 配置：配置公开接口和受保护接口；
- UserMapper：按邮箱查询认证所需字段。

## 编写步骤

### 第 1 步：画认证数据流

分别画出：

```text
注册 → 校验 → BCrypt → 保存摘要
```

```text
登录 → 查询用户 → 比较密码 → 签发 JWT → 返回 Token
```

```text
带 Token 请求 → 过滤器 → SecurityContext → Controller → Service
```

### 第 2 步：完成注册

关注：

- 邮箱冲突；
- 密码摘要；
- 用户响应字段；
- 日志脱敏。

### 第 3 步：完成登录

关注：

- 查询不到用户和密码错误的统一语义；
- Token 的身份信息和过期时间；
- 客户端可以看到载荷，但不能伪造签名。

### 第 4 步：保护业务接口

逐项验证：

- 注册和登录是否公开；
- `/api/users/me` 是否要求登录；
- 过滤器是否在 Controller 之前运行；
- 当前用户 id 是否从安全上下文取得。

## 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 注册成功 | 密码摘要入库，响应无密码 |
| 邮箱重复 | 409 |
| 登录成功 | 返回可用 JWT |
| 密码错误 | 401，不泄露账号细节 |
| 无 Token 访问业务接口 | 401 |
| Token 无效或过期 | 401 |
| 已认证但业务权限不足 | 403 |
| 获取当前用户 | 返回当前用户 VO |
