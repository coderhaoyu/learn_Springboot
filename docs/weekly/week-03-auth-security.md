# 第 3 周：认证与安全

> 建议投入：17–20 小时
> 对应总计划：[PLAN.md](../../PLAN.md)

## 当前目标

实现注册、登录和当前用户接口，理解带 Token 的请求如何在到达业务 Controller 之前建立当前用户身份。

本周只解决“你是谁”，暂时不实现情侣关系和挑战权限。

## 范围调整（2026-09-03）

原计划里“已认证但没有业务权限的请求能够返回 403”这一项**移出本周**。

原因是 403 有两种来源，而这个项目只有第二种：

- **角色不够**（普通用户 vs 管理员）：需要 role 字段加 `hasRole`。但本应用是双人情侣产品，业务上没有管理员这个角色，为了练机制去造一个 ADMIN 属于为形式增加复杂度。
- **资源不归自己**（同为普通用户，但这条数据不是你的）：这才是本应用真实存在的 403，比如别人的情侣关系、别人的签到、别人的动态。它判的是数据归属，Security 配置判不了，必须在 Service 里比较当前用户 id 和资源所属 id。

所以 403 推到第 4 周和情侣绑定一起做，正好对应总计划里“将关系权限放在 Service 判断”。

本周因此还剩一件事：第 1、2 周为了练 CRUD 写的管理型接口，现在对任何登录用户开放。

本次决定：**只删 `POST /users`，其余保留。**

删 `POST /users` 的理由：它和 `/auth/register` 功能重复，而且插入时 password 传的是 null 而列是 `NOT NULL`，严格模式下本来就会报错。跟着一起删的是 `UserService.addUser` 和 `CreateUserRequest`（除这两处外没有别的地方引用）。

**不要删 `UserMapper.addUser` 和 XML 里的 `<insert id="addUser">`** —— `AuthService.registerUser` 用的是同一个 Mapper 方法，删了注册就坏了。

`GET /users`、`GET /users/by-email`、`PUT` 和 `DELETE /users/{id}` 保留，作为学习期查数据和试接口的入口。

## 已知遗留（暂时接受）

保留上面那几个接口意味着：**任何注册用户凭自己的 token 就能读到全部用户的姓名、邮箱和年龄，也能改删任意用户。**

这是学习阶段有意接受的，不是漏掉的。必须处理的时间点，以先到的为准：

- 这个应用要给自己以外的人用之前（哪怕只是拿局域网 IP 给对象的手机试用）；
- 第 4 周做资源归属校验时，顺手把这批接口一起收掉。

## 需要创建或调整的职责

- 认证 Controller：注册和登录入口；
- 认证 Service：注册规则、密码比较和 Token 签发；
- 登录和注册 DTO/VO：定义安全边界；
- JWT 工具：生成、解析和验证；
- JWT 过滤器：读取请求头并建立身份；
- Security 配置：配置公开接口和受保护接口；
- UserMapper：按邮箱查询认证所需字段。

## 编写步骤

### 第 1 步：画认证数据流

分别画出：

```text
注册 → 校验 → BCrypt → 保存摘要
```

```text
登录 → 查询用户 → 比较密码 → 签发 JWT → 返回 Token
```

```text
带 Token 请求 → 过滤器 → SecurityContext → Controller → Service
```

### 第 2 步：完成注册

关注：

- 邮箱冲突；
- 密码摘要；
- 用户响应字段；
- 日志脱敏。

### 第 3 步：完成登录

关注：

- 查询不到用户和密码错误的统一语义；
- Token 的身份信息和过期时间；
- 客户端可以看到载荷，但不能伪造签名。

### 第 4 步：保护业务接口

逐项验证：

- 注册和登录是否公开；
- `/users/me` 是否要求登录；
- 过滤器是否在 Controller 之前运行；
- 当前用户 id 是否从安全上下文取得。

### 第 5 步：删掉 `POST /users`

这一步不是加权限，是删一个重复的入口：注册已经由 `/auth/register` 负责，`POST /users` 既绕过密码加密，又往 `NOT NULL` 的 password 列插 null。

按“谁引用它”的顺序往下删：Controller 方法 → `UserService.addUser` → `CreateUserRequest`。

删之前先搜一遍 `addUser`，确认自己分得清两个同名方法：`UserService.addUser` 该删，`UserMapper.addUser` 不能删（`AuthService.registerUser` 在用）。删完编译一次，再注册一个新账号，确认注册没坏。

## 验收矩阵

| 场景 | 预期结果 |
|---|---|
| 注册成功 | 密码摘要入库，响应无密码 |
| 邮箱重复 | 409 |
| 登录成功 | 返回可用 JWT |
| 密码错误 | 401，不泄露账号细节 |
| 无 Token 访问业务接口 | 401 |
| Token 无效或过期 | 401 |
| 获取当前用户 | 返回当前用户 VO |
| 两个账号各自请求 `/users/me` | 各自返回自己的信息 |
| `POST /users` 已删除 | 请求返回 404，注册仍然正常 |
