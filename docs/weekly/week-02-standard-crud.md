> 建议投入：16–20 小时

## 当前目标

在数据库 CRUD 已经跑通的基础上，补齐接口边界、分页和异常体系，让客户端能稳定地区分成功、参数错误、资源不存在与业务冲突。

## 本周完成标准

- [x] 新增和修改使用独立 DTO，响应使用 VO，不直接暴露 Entity。
- [x] 姓名、年龄、邮箱等请求字段具备 Bean Validation 规则。
- [x] 用户列表支持 `page`、`size` 分页，并返回总数。
- [x] 普通接口统一使用 `ApiResponse<T>`。
- [x] 分页统一使用 `PageResult<T>`。
- [x] 参数错误返回 400，用户不存在返回 404，邮箱冲突返回 409。
- [x] Controller 中没有业务规则，Service 中没有 HTTP 响应拼装。

## 验收矩阵

| 场景 | 状态码 | 关键检查 |
|---|---:|---|
| 新增成功 | 2xx | 返回 VO，不包含内部字段 |
| 请求字段非法 | 400 | 明确指出非法字段 |
| 用户不存在 | 404 | Service 判定业务结果 |
| 邮箱重复 | 409 | Service 校验与唯一约束共同保护 |

## 学习重点

- DTO/VO 是服务端接口边界，不只是复制 Entity。
- 参数校验解决“格式是否合规”，Service 解决“业务是否允许”。
- 唯一约束是数据一致性的最后防线，不能只依赖先查后写。
- 全局异常处理把 Java 异常统一翻译为 HTTP 语义。

## 周末复盘问题与解析

### 1. DTO、Entity、VO 分别在哪一层出现？各自承担什么职责？

- **DTO（Data Transfer Object - 数据传输对象）**：
  - **出现层级**：`Controller`（作为入参）→ `Service`（业务参数传递）。
  - **核心职责**：**输入边界**。用于接收前端请求体或查询参数，限制前端可提交的字段（防止恶意篡改未开放字段），并配合 `@Valid` 执行参数格式校验。
- **Entity（领域实体）**：
  - **出现层级**：`Service` ↔ `Mapper` ↔ `MySQL`。
  - **核心职责**：**数据持久化映射**。与数据库表字段 1:1 对应，属于服务端内部私有数据结构，严禁直接暴露给前端。
- **VO（View Object - 视图对象）**：
  - **出现层级**：`Service`（Entity 转 VO）→ `Controller`（作为响应数据 `T` 返回）。
  - **核心职责**：**输出边界**。控制对外响应的数据结构，过滤掉敏感字段（如密码、内部状态），提供前端所需的数据格式。

### 2. 为什么分页通常需要数据查询和总数查询两条 SQL？

- **数据查询（`SELECT ... LIMIT #{limit} OFFSET #{offset}`）**：只捞取当前页所需的切片数据，防止大表全量查询导致 Java 内存溢出（OOM）。
- **总数查询（`SELECT COUNT(*) FROM ...`）**：获取符合筛选条件的总记录数。前端需要总数来计算总页数、渲染分页条页码组件，并判断是否存在下一页。

### 3. `page` 与 `offset` 有什么区别？

- **`page`（页码）**：从 1 开始，符合人类认知和前端 UI 交互的思维模型。
- **`offset`（偏移量）**：从 0 开始，代表底层数据库存储引擎在读取数据前需要跳过的记录行数。
- **换算公式**：`offset = (page - 1) * size`。

### 4. 400、404、409 分别对应什么问题？

- **`400 Bad Request`（参数格式非法）**：请求体/参数语法或格式错误（如邮箱不符合正则、年龄小于 0、必填字段为空）。**在进入具体业务状态前即可判定非法**。
- **`404 Not Found`（资源不存在）**：请求 URI 所指定的资源（如 `/users/999`）在服务端/数据库中未找到。
- **`409 Conflict`（业务状态冲突）**：请求格式完全正确合规，但**与服务器当前的数据状态产生冲突**（例如注册时邮箱已被其他用户占用）。

### 5. 如果两次相同邮箱请求同时到达，只在 Service 中先查询是否足够吗？

- **不够安全**。这是典型的并发“先查后写”竞态条件（Race Condition）。
- **并发场景**：若两个并发请求在同一毫秒到达，线程 A 和线程 B 同时执行 `findByEmail`，由于此时双方均未写入，查出的结果都为 `null`；随后两线程均执行 `INSERT`。
- **解决方案**：
  - `Service` 的查重是提供友好错误提示的业务防线；
  - **数据库的 `UNIQUE` 唯一约束是保证数据一致性的最后一道铁律防线**。两者必须结合使用。
